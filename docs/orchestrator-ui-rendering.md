# Orchestrator UI-5：描画方式と負荷計測

対象branch: `codex/mgr-1-manager-overview`。比較元: `358e472cfb648a05f64e86cb41e0de97ae213136`。

## 計測範囲

Windows / Python 3.13.14 / Pillow 12.2.0。実データ・Collector・RunMonitor・Provider・外部通信は使用しない。

- 更新経路は既存の偽Tk・偽Monitorで時間と呼出回数を計測。
- 描画APIは**単体テストとは別の、非表示Tkプロセス**で合成TASK 5 / 20 / 50件を計測。比較元の表示モジュールを `git show` でメモリに読み込み、作業ツリーを切り替えず比較する。
- 同一モデルの繰返しは100回、円形背景の繰返しは50回。初回生成・旧画像読み込みは各1回。値は参考値で、OS負荷・フォントキャッシュで変動する。
- 非表示TkはWindowsコンポジターの画面提示・入力遅延・実際のスクロール操作を含まない。以下を実機の視覚／操作確認完了とは扱わない。

再計測（開発用。起動前に作業branchを確認）:

```powershell
python -m tests.benchmark_orchestrator_ui --tk
```

通常のunittestではこの入口を呼ばず、実Tkを起動しない。計測プロセスには45秒の診断タイムアウトがある。旧方式の画像読み込みが遅い環境では時間制限に達する場合がある。

## 結果と原因

更新経路（偽部品、1件の合成Run、平均ms）:

| 処理 | 変更前 | 変更後 |
|---|---:|---:|
| `_tick()` | 0.0774 | 0.0525 |
| `apply_snapshot()` | 0.0696 | 0.0499 |
| `_refresh_board()` | 0.0219 | 0.0219 |
| Workflow・Run同時受信tickのboard更新回数 | 4回 | 1回 |

`_render_selected()` 内のboard更新と、呼出元からの更新が重複していた。同一tick内では状態を先に反映し、最後に選択・安全停止対象を含む表示を1回だけ更新する。単独の `apply_snapshot()` は引き続き即時更新する。イベントもデータもないtickでは再描画しない。Run取得間隔・停止前確認は変更していない。

非表示Tkでの実API計測（ms）:

| TASK数 | 初回 `set_model` 前→後 | 変更なし `set_model` 前→後 | リサイズイベント 前→後 | 同じ寸法の `_draw_ring` 前→後 |
|---:|---:|---:|---:|---:|
| 5 | 5.5781 → 4.8301 | 0.6569 → 0.0010 | 5.8388 → 0.0104 | 4.3970 → 0.0002 |
| 20 | 10.6924 → 25.8666 | 0.6995 → 0.0033 | 4.9418 → 0.0072 | 4.8746 → 0.0002 |
| 50 | 25.3724 → 42.1704 | 0.7007 → 0.0083 | 4.8404 → 0.0085 | 4.7728 → 0.0002 |

- 100連続リサイズでの円形描画呼出し: **100回 → 1回**。90msのdebounceで最後の寸法に追従する。イベント値には間引き待機時間・ワーカー生成時間は含まれない。
- 初回カード生成は20/50件では重くなった。Canvasの文字・状態部品が増えたため。フォント共有・文字幅の二分探索・512件の文字レイアウトキャッシュで、最適化前の新カード50件約171msを約42msまで抑えた。
- 初回の上記値は装飾ワーカーの完了／画面提示までの時間ではない。カード操作部品とテキストは先に生成し、背景だけ準備後に差し替える。
- 同じモデルではカード・ヘッダーを更新しない。TASK IDのキー、選択・フォーカス・スクロール位置を維持し、追加・削除・工程変更のみ配置を変える。

キャラクター（非表示Tk）:

| 処理 | 変更前 | 変更後 |
|---|---:|---:|
| 1フレーム転送（100回平均） | 11.7654ms | 7.7887ms |
| 全スプライトのTk読み込み | 12,293.7909ms | 廃止 |
| 準備済みフレームの参照 | — | 0.0008ms |

全PNGを透過化してから `tk.PhotoImage(data=...)` に渡す旧処理が、メインスレッドの長い停止要因だった。別試行では約16.6秒、診断タイムアウト時のスタックもTk画像生成を指していた。

新方式はPillowで72フレームをワーカー準備し、UIには240×333（または縮小）の1フレームだけ転送する。準備の単体計測はidle・scale=1で約414ms。素朴な背景ピクセル探索では約9.8秒だったため、連続した水平領域をCの正規表現走査で取得して外周接続を解析する方式に変更した。**414msはワーカー時間で、UIスレッドの処理時間ではない。**

最終装飾生成の単体計測（各5回平均）は、カード192×108で4.591ms、円形650×630で132.599ms、左右パネル220×650で26.381ms。すべて専用ワーカーで実行し、UIは生成待ちを同期的に行わない。

## 描画構成と上限

- `orchestrator_art.py`: 2倍解像度で丸角・縦グラデーション・細い境界・控えめな光彩を生成し、LANCZOSで縮小。中央は4色の滑らかな円弧・矢印・バッジ。単一ワーカー、要求最大24件、LRU最大24枚かつ800万画素。1生成は400万画素以下に制限する。
- `orchestrator_cards.py`: Canvas上の画像背景とネイティブの文字・状態点を分離。ホバー・フォーカス・選択を強調。文字幅を測って省略し、詳細は既存のクリック／キーボード経路へ渡す。カード背景は16px単位の幅で共有し、カードごとのTk画像は現在の1枚だけ。左右パネルにも丸角背景を使う。
- `orchestrator_loop.py`: 寸法が同じ円形装飾を再生成しない。カード更新と背景・キャラクター更新は独立。Archiveは初期折りたたみ。
- `sprite_renderer.py`: 最新要求1件、準備済みのmood/scaleはLRU最大2組。最大でRGBA約46MBのフレームキャッシュと、処理中1組の一時領域を使用。既存6種類・72フレーム・12fpsを維持。全スプライトのTkデコードを行わず、同サイズでは現在のImageTk画像へpasteする。
- 閉鎖時はリサイズ／装飾／カード／アニメーションの予約を解除し、ワーカーに停止を通知。進行中のPillow処理の終了後にワーカーが終了する。ワーカーからTkを呼ばない。

原画像は変更していない。背景候補のうちフレーム外周へ4近傍でつながる部分だけを透明にする。内部に閉じた暗色の服・小物を保持し、元からalphaがある画像はそれを尊重する。背景につながる暗色の輪郭は影響を受ける余地があり、全6モードの実表示確認は残る。

## Windows配布と依存

`requirements-dcc-ui.txt` に **Pillow==12.2.0** を明記した。この作業では既存のPython環境・bootstrap・配布設定を変更せず、追加インストールもしない。検証に使用したWindows Pythonには既に導入済みだった。

高品質描画には、**DCCを実際に起動するPython環境**へのPillow導入が必要:

```powershell
<その環境のpython.exe> -m pip install -r requirements-dcc-ui.txt
```

Pillow未導入時は固定文で簡易描画を示し、共有Canvasのアニメーションを無効にする。旧方式の長い全画像デコードへ戻さない。開始設定・利用枠・安全停止などの操作は維持する。通常の独立CharacterViewの既存経路は変更しない。

このrepoにはDCC専用の凍結ビルド定義が確認できなかったため、exe配布での自動同梱は保証しない。凍結配布を行う場合はPIL.ImageTk・_imagingtk・Tcl/Tkを含む成果物を、対象Python／Windowsで別途確認する。配布容量と画像キャッシュ分のメモリが増える。有料API・画像ダウンロードは追加していない。

## 回帰・安全性

新規描画テストは、生成画像の寸法／状態差、外周透過と内部暗色保護、元alpha保持、6種×72フレーム、キャッシュ／要求／画素上限、停止・フォールバック、文字幅・選択、5/20/50件のカード再利用、リサイズ間引き、tickの更新集約を検証する。Tk・Canvas・Provider・Monitorは偽物で、実AI・外部通信・本番保存先へ接続しない。非表示Tkの計測とは入口を分ける。

既存の開始前確認、provider/利用枠、ログコピー、選択TASKと停止対象、候補操作、Manager読取表示の関連テストも実行する。Runner・Workflow・承認境界・報告箱実装・app.py・WF-6・AI推論設定は変更しない。

## 残る実機確認

静的な装飾合成画像は確認したが、**実際のOrchestrator画面の視覚・操作確認は未実施**。

- 実起動に使うPythonのPillow検出、DPI 100/125/150%、最大化・縮小時の日本語、文字省略と詳細表示。
- 5/20/50件での縦スクロール・カード移動・ホバー・Tab/Enter/Space操作・選択維持。
- 連続リサイズ時の追従、装飾の準備中・切替時のちらつき、円弧・カード・キャラクターの重なり。
- 6モード全フレームでの暗色輪郭・透過境界・残像、初回準備時の案内表示。
- 開始設定、Main/Reviewer、Claude/Codex利用枠、上部ログコピー、報告箱callback、安全停止対象表示・停止前確認。
- 表示中の入力遅延・スクロール性能・長時間利用のメモリ推移・閉鎖時の予約解除。非表示Tkの数値だけで合格としない。
